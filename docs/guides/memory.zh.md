# SQLite 三层记忆

每个 `PICOCLAW_HOME` 有一份记忆库，位于其 `state/memory/memory.sqlite3`。默认路径是 `~/.picoclaw/state/memory/memory.sqlite3`。workspace 只存放文件和技能，切换 workspace 不会切换记忆；不同的 home 各自独立。

| 层级 | 何时加载 | 如何清除 |
| --- | --- | --- |
| 近期聊天与摘要 | 按原会话路由加载，按 token 预算裁剪，保留完整工具调用和结果 | `/new` 或 `/clear`；`/new <问题>` 清除后执行新问题 |
| 重要偏好 | 每轮向终端和有权限的私聊注入实例偏好，最多 12 条、每条 160 字、总计 500 token | 直接说要删除哪项偏好；换模型、重启和 `/new` 不清除 |
| 永久记录 | 不自动加载，由模型调用 `memory_search` 检索；最多 5 条，带日期和出处 | 直接说要删除哪条记录；不会自动过期 |

本地 `picoclaw agent` 和通过现有渠道访问规则的飞书、微信私聊直接共用偏好和永久记录。渠道的 `allow_from` 决定哪些发送者能进入私聊；如果留空或放行所有人，能发私聊的人也能访问这一份记忆。群聊和合成任务没有私人记忆权限。终端和两端 IM 的聊天历史、摘要按会话隔离。IM 文件和执行工具不能绕过这些限制访问记忆库。

```text
以后用中文、回答简短一点
帮我记一下，2026-05-21 原神打到第三章
查查我上次原神玩到哪了
原神进度改成第四章
删掉上次记的塞尔达宝箱清单
删除简短回答的偏好
```

明确新增的「帮我记一下……」「记录一下……」直接保存，无需等模型。其他明确的管理请求由 Agent 用 `memory_write` 写入；只有事务提交成功才确认。更正和删除永久记录先用 `memory_search` 查找。用肯定式指令明确指定记录编号、旧值和新值，且旧值只出现一次时，可以立即更正。把偏好和其他任务放在同一条消息里时，助手会按普通对话处理。无法确定替换范围时，先核对修改前后的内容，再在同一会话回复「确认更正」。更正后保留原编号、出处和未指定的日期。如果有多个候选，回复「删第二条」或「11 月 21 日那条」即可。候选和更正预览仅在当前会话有效，五分钟后过期。`/new` 和 `/clear` 会清掉它们。

删除后，删除前已入队的聊天不能恢复刚删掉的偏好或记录。偏好只阻止同键的旧证据；删永久记录时，旧队列不再生成永久记录，但仍可整理偏好。新消息照常整理。普通聊天继续走后台整理。

明确写入可指定 ISO 日期；未指定时用偏好时区，没有时区偏好则用 Gateway 时区。检索支持关键词、别名、标签、日期范围和「原神」这样的中文短词，最多返回五条带来源的摘录。旧版 `/memory` 和 `/preference` 仍可用，例如 `/memory export` 逐条导出 JSON。

保存时可用结构化输入指定分类，例如 `/memory add {"text":"原神玩到第三章","category":"日常/游戏"}`。每条记录最多有一个分类路径，保存在可空的 `records.category` 字段里。按「日常」过滤也能命中「日常/游戏」。`tags` 存「宝箱」「神庙」等主题词，`aliases` 存「旷野之息」「BOTW」等别名。即时保存优先采用明确指定的分类或可靠的本地规则，命中时不调用分类模型。否则先以 `other` 提交并立即确认，再调用一次模型给同一条记录补分类、标签和别名。模型不确定、失败、超时或进程先退出时，记录留在 `other`，仍可按原文检索。此流程不进入定时整理队列，CLI 退出不等待；分类期间记录若已被更正或删除，结果会被丢弃。

检索可同时试几种说法。例如主词「宝箱」，备选「箱子」「神庙」「BOTW」。备选各自查询，结果按原词优先合并、去重，日期和用户明确要求的分类过滤适用于每种查询。只提到游戏名不会限定分类。

## 后台整理偏好和永久记忆

Gateway 每 30 秒检查待整理的会话。有新的可信私聊文本且空闲满 2 分钟时会批量整理；持续活跃的会话在首条待处理内容满 10 分钟后也可以进入整理。终端也可以登记待整理内容，由使用同一数据目录的 Gateway 处理。每次最多取 20 条新消息，每会话最多保留 200 条待整理内容；没有新增内容时不调模型。群聊、未通过渠道规则的消息、转发和附件不作为依据。

后台只保存有原话依据的长期偏好和事实，无需确认。偏好按键更新，新建最多 12 条；已满仍可更新已有项，提示最多加载 12 条，并受长度和 token 预算限制。滚动记录按主题更新，例如「原神进度」会更新原有记录与出处，保留原编号；确实不同的带日期事件仍可分开保存。没有变化就不重复改写，整理也不会把旧进度写回到更新的数据上。成功更新后，飞书或微信原私聊会收到一条变更数量摘要。设置 `memory.disable_auto_capture: true` 可关闭后台整理，明确保存仍立即生效。

`/new` 和 `/clear` 会放弃当前会话尚未整理的内容；已经保存的偏好和记录保留。自动整理从升级后新增的消息开始，不回扫旧聊天。

## 初始化与持久化

首次启动会直接创建 SQLite v1 数据库。工作区中的 JSONL、Seahorse 和 Markdown 旧记忆文件会被忽略。当前版本支持备份和恢复结构匹配的 SQLite v1 数据库。

普通问答和常规工具轮次在轮末一次提交。长轮累计 8 个完整工具批次或待提交消息达到 512 KiB 时，等这一批所有调用都有结果后再落盘；重启只可能丢失尚未提交的上下文。修改偏好、写入记录及执行 `/new`、`/clear` 仍立即提交。上下文超限重试只裁剪该次提示，异步摘要只删除旧消息并更新摘要。迟到的摘要不能覆盖已清除的会话。

删除旧消息后，SQLite 会复用空闲页，数据库文件不一定立即变小。当前不启用 WAL 或降低同步级别；请求路径不运行 `VACUUM`。确实需要缩小时，安排备份和停机恢复。将来若启用 WAL，应监控其大小和 checkpoint 进度，避免每轮强制截断。

用 `picoclaw memory backup <file>` 保存 SQLite 快照，停机后用 `picoclaw memory restore <file>` 恢复，恢复会保留替换前快照。备份和恢复适用于正式 v1 快照，并包含待整理内容和主题。恢复旧快照会回退之后的记忆变更。备份包含私人信息，请放在工作区外。配置、工作区资源和媒体文件另行备份。
